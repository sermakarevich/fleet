# tweet_watch R7 (worker bead body template) — failure modes

Scope: repo file (e.g. `docs/tweet_watch/WORKER.md` or a fleet
template) containing the copy-paste bead body for the recurring run:
the ordered steps R1->R6 with exact KB paths, the `x` CLI invocations,
and the HIGH-only proposal rule. Observable: the file exists in the
repo and a worker following it verbatim performs steps R1-R6.
Step-level edge cases (fetch/parse, scoring, dedupe, gating,
persistence, file formats) live in M1/M2/M3 and R1-R6; this file
covers the template only: missing/wrong/stale instructions, a worker
following it verbatim into a bad runtime situation, and what the
worker must do instead of improvising (stop and report, never invent
paths, commands, or policy).

The template names these exact paths and commands — any deviation is
a template bug, not a worker judgment call:
`/Users/sergii/.ai/knowledge/media/x/watchlist.md`,
`/Users/sergii/.ai/knowledge/media/x/watch_state.json`,
`/Users/sergii/.ai/knowledge/media/INTERESTS.md`,
`/Users/sergii/.ai/knowledge/media/x/replies/`,
`x watch add user:<handle>` then `x watch check --format json`,
one `ask_human` call per HIGH tweet, reply files
`<date>-<id>.md` only on confirmation.

## Bad or missing input

- F1 template file missing from the repo or at an undocumented path
  (worker opens `docs/tweet_watch/WORKER.md` and it is not there).
  Expected: error naming the expected path; the run does not proceed
  on a remembered or reconstructed procedure. A missing template is a
  hard stop, never "follow R1-R6 from memory".
- F2 template omits the R1 ensure step (no "create watchlist with 5
  seeds if missing" instruction, or seed handles wrong/missing —
  `omarsar0`, `typesafeai`, `cloneisjun`, `goodhartproof`,
  `SakanaAILabs`). Expected: template bug — fix the template, do not
  let the worker invent seeds. A worker that finds no watchlist and
  no instruction must stop with an error naming the watchlist path,
  never create a file with guessed handles.
- F3 template lists a wrong KB path (typo in `watch_state.json`,
  `replies/` vs `reply/`, `~/.ai` vs the absolute
  `/Users/sergii/.ai/knowledge/media/x/` prefix). Expected: error
  naming the path as written; the worker never falls back to a
  "likely" path. KB files outside the listed paths are never read or
  written — writing state to the repo instead of the KB is a data-loss
  bug (R2 re-emits everything next run).
- F4 template omits or mangles an `x` CLI invocation (missing
  `watch add` step, `check` without `--format json`, invented flags).
  Expected: the worker runs exactly the documented invocations; an
  undocumented flag or a missing `--format json` is a template bug to
  fix, not something to paper over with `2>/dev/null` or ad-hoc
  parsing. Unparseable output surfaces as an error naming the handle
  (M2), never fabricated tweets.
- F5 template omits the state-persistence step (R2 "persist newest
  seen id per handle back to `watch_state.json`"). Expected:
  template bug — without the write-back every run re-emits the same
  tweets and re-proposes the same drafts. A worker that reaches end
  of run with no persist instruction must report it, not exit
  "successfully" while leaving state unchanged on a non-empty run.
- F6 template omits the HIGH-only proposal rule (says "propose
  interesting tweets" without HIGH/MEDIUM/LOW, or drops "MEDIUM/LOW
  never trigger a proposal"). Expected: the HIGH-only gate in R5
  still binds — the worker proposes HIGH only. A template that would
  have the worker propose MEDIUM/LOW is a template bug; the worker
  must not spam the operator with non-HIGH proposals to "be helpful".
- F7 template omits the R4 recency-dedupe step (no "read replies from
  the last 3 days and compare before proposing"). Expected: no
  proposal without the dedupe verdict (R5-F20, fail closed). The
  worker stops the proposal phase with an error naming the missing
  check rather than proposing unchecked drafts.
- F8 template omits the voice-notes rule (no pointer to INTERESTS.md
  voice notes: plain language, no hype words, concrete observation
  or number first, abbreviations explained on first use). Expected:
  drafts that cannot be voice-checked are not proposed (R5-F8). The
  worker aborts proposals for the run, not proposes unstyled drafts.
- F9 template omits the confirmation gate (says "store drafts" or
  "store proposed replies" without "only when the operator confirms
  posting with a reply id"). Expected: unconfirmed drafts store
  nothing (R6 observable). A template ordering that writes reply
  files before confirmation is a template bug — the worker must not
  create `<date>-<id>.md` without a posted id.
- F10 template instructs committing KB files to the repo (watchlist,
  state, or replies via `git add`). Expected: refused — KB files are
  written directly to `/Users/sergii/.ai/knowledge/...` and never
  committed (spec deliverables rule). The worker reports the bad
  instruction instead of following it.
- F11 template step order swapped (e.g. score before fetch, persist
  before propose, R6 before R5). Expected: R1->R6 order binds
  regardless of document order. Persisting state before the check
  completes, or writing reply files before asking, violates the R2/R6
  observables; the worker follows numbered R-order, not page order,
  and reports the template defect.

## Boundary values

- F12 quiet run (no new tweets, or zero HIGH tweets). Expected: the
  template must state the quiet exit explicitly — zero `ask_human`
  calls, zero new files, successful run. A template with no quiet-run
  instruction invites a "nothing to report" proposal or a spurious
  error; both violate R5-F10.
- F13 N HIGH tweets -> N proposals (3 HIGH tweets -> 3 `ask_human`
  calls, each with its own link + draft). Expected: the template must
  forbid batching into one call and forbid fanning one tweet into two
  calls (R5-F11). A template silent on cardinality produces batched
  proposals the operator cannot confirm per-tweet.
- F14 draft at or over the X length limit. Expected: the template must
  instruct rewrite/trim before proposing and forbid auto-truncation
  mid-word (R5-F12). A template that says "propose the draft" with no
  length check yields unpostable proposals.
- F15 template drift after an R1-R6 change (INTERESTS.md gains a core
  topic, reply format gains a field, `x` CLI changes output shape,
  but the template still documents the old shape). Expected: the
  numbered requirement (R1-R6 text) wins over the template copy. The
  worker reports the mismatch naming both sources instead of
  following the stale copy verbatim into a wrong write.

## External errors

- F16 `x` CLI missing or failing on the run machine (`command not
  found`, non-zero exit, unparseable stdout). Expected: the template
  must instruct fail-loud with the handle named and state untouched
  for the failed scope (R2-F3/M2), so the next run retries. A
  template telling the worker to "continue with cached tweets" or
  invent candidates violates M2's never-fabricates-tweets rule.
- F17 INTERESTS.md missing or unreadable at run time. Expected: the
  template must instruct aborting proposals for the run (R5-F8), not
  scoring by gut feel. Tweets stay new via persisted state and are
  re-driven next run.
- F18 `ask_human` tool failing mid-batch (tool error, timeout,
  operator console unreachable). Expected: the template must instruct
  recording that tweet as unproposed, continuing with the remaining
  HIGH tweets, and exiting non-zero/log-loud (R5-F15) — never treating
  the failure as a decline or a confirmation.
- F19 KB parent dir missing (`media/x/` itself absent, not just the
  files). Expected: the template must instruct `mkdir -p` via the R1
  ensure path, then proceed. Not an error, but only if the template
  says so — the worker never creates directories under unlisted
  paths.
- F20 schedule/cron broken around the template (cron entry deleted,
  `--overlap skip` lost, manual runs only). Expected: out of template
  scope — the template covers one run R1->R6, not the schedule (R9).
  The worker performs exactly one pass and exits; it never loops,
  retries on a timer, or reinstalls the schedule from inside the run.

## Wrong state

- F21 state file corrupt when a verbatim run starts (invalid JSON,
  wrong shape). Expected: the template must instruct abort-before-fetch
  with an error naming the state path (R2-F4/M1), never reset to `{}`.
  A template silent on corruption gets "helpful" resets that re-emit
  every tweet ever seen.
- F22 watchlist edited mid-run (handle removed between R1 and R5).
  Expected: the template must instruct working the R1 snapshot for
  this run (R5-F22); next run picks up the edited list. Re-reading
  mid-run mid-batch causes half-processed handles and skipped
  persistence.
- F23 source tweet deleted between fetch and proposal (link 404s).
  Expected: the template must instruct proposing once with cached text
  plus a dead-link note (R5-F19), never silently dropping an emitted
  tweet and never proposing without the link.
- F24 operator already replied from outside the worker (manual reply
  on X, no file in `replies/`). Expected: the template must state the
  documented behavior — still propose (R5-F21); the linked thread is
  the backstop. A template inventing an "X liveness check" step sends
  the worker beyond its tools and stalls the run.
- F25 confirmation arrives without a reply id ("posted", no id or
  link). Expected: the template must instruct storing nothing and
  logging pending-confirmation with the source id (R5-F18/R6-F3),
  never inventing an id to complete the filename.

## Concurrency

- F26 two runs following the same template overlap (manual
  `schedule run` colliding with the 30-minute tick; the installed
  schedule uses `--overlap skip` so this is manual-only). Expected:
  the template must state no-locking semantics: both runs may call
  `ask_human` independently (R5-F23); double confirmation converges
  via idempotent same-path R6 writes (R6-F21). The template must not
  instruct lockfiles, state-file merges, or de-duplicating the other
  run's proposals — the operator seeing a duplicate proposal is the
  accepted backstop, and R4 blocks repeats once one is persisted.
- F27 R4 listing racing an R6 write from a concurrent run.
  Expected: atomic rename means the listing sees the complete file or
  misses it, never a half-written body (R6-F22). The template must not
  add read-modify-write cycles (e.g. "append to an index file") that
  would break under overlap — one file per reply, one rename per
  write.
