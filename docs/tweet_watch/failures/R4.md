# tweet_watch R4 (recency dedupe) — failure modes

Scope: before proposing any draft, read reply files from the last 3 days
via M3 and drop (or flag for rewrite) any draft near-identical in wording
or point to an existing reply. File listing/window/read-write failures
live in M3; scoring/proposal/persistence edge cases live in R3/R5/R6;
this file covers the dedupe decision only: given (draft text, in-window
reply bodies), block or pass.

Comparison is over normalized text (case-folded, whitespace-collapsed,
punctuation-insensitive) and over the point made, not exact bytes: a
paraphrase restating the same claim with the same evidence is
near-identical; the same topic with a new concrete observation is not.

## Bad or missing input

- F1 empty or whitespace-only draft. Expected: flagged for rewrite, never
  proposed — there is nothing to compare and nothing new added (R5
  requires a concrete observation). Logged with the tweet id; other
  tweets in the batch still processed.
- F2 draft with only a link, mention, or emoji and no proposition
  ("this 👇 https://…"). Expected: flagged for rewrite; a content-free
  draft can neither be cleared nor blocked by wording comparison, and
  proposing it would violate the R5 adds-something-new rule.
- F3 in-window reply files with empty bodies (0-byte or boilerplate-only
  files, M3-F5). Expected: contribute nothing to the comparison; they
  never block a draft. Run continues.
- F4 same point in a different language (yesterday's English reply on
  verifier false-positive rates, today's draft restates it in
  Ukrainian). Expected: blocked — near-identical covers the point, not
  just the wording. Translation is not a new angle.
- F5 draft differing from an in-window reply only by URL, handle, or
  hashtag ("same benchmark paragraph, swapped link"). Expected:
  blocked; link/mention swaps do not make the point new.
- F6 draft differing only by case, whitespace, line breaks, or
  punctuation. Expected: blocked — normalization happens before
  comparison, so cosmetic edits never slip past.

## Boundary values

- F7 paraphrase vs new angle (the core line). Draft restating the same
  claim with the same evidence ("verifier models cut false approves;
  we saw 30% fewer bad merges") in fresh words -> blocked. Draft on
  the same topic with a new concrete observation (same verifier
  thread, but the draft adds cost-per-verified-task numbers not in any
  in-window reply) -> passes. Rule: same claim + same evidence =
  block; same topic + new observation/number = pass.
- F8 window edge: draft identical to a reply from exactly 3 days ago
  (run date `2026-09-26`, reply `2026-09-23-*.md`) -> blocked; draft
  identical to a reply from 4 days ago (`2026-09-22-*.md`) -> passes
  (window is inclusive of the 3rd day per M3-F8; older than 3 days
  does not block per the R4 observable).
- F9 draft matching one of several in-window replies (5 replies in
  window, draft copies the 4th). Expected: blocked — the draft is
  compared against every in-window body, not just the latest.
- F10 short generic overlap ("Agreed, evals matter", "costs add up").
  Expected: passes — shared generic words with no shared point are not
  near-identical. Blocking on 3-word overlaps would veto every draft
  on a busy topic.
- F11 draft embedding an old point plus new material (one paragraph
  repeats yesterday's verifier paragraph verbatim, second paragraph
  adds a new latency number). Expected: flagged for rewrite (cut the
  repeated paragraph), not dropped outright and not passed as-is —
  the spec allows "flag for rewrite" precisely for this shape.
- F12 empty in-window set (no replies in the last 3 days, M3-F11) or
  replies dir missing (M3-F1). Expected: all drafts pass; empty history
  is not an error and never blocks.

## External errors

- F13 replies dir unreadable mid-run (permissions, KB path unmounted;
  M3-F13) or a single in-window file unreadable (M3-F14). Expected:
  abort the run with the M3 error naming the path; do NOT fall back to
  an empty history — that would silently disable the dedupe and risk
  proposing a near-duplicate. Fail closed.
- F14 in-window file with corrupt body (binary garbage, truncated
  mid-line; M3-F18). Expected: the file still counts as present, read
  best-effort; a draft is never passed on a decoding technicality.
  Never auto-delete or "repair" the file.

## Wrong state

- F15 future-dated reply file (`2026-09-27-*.md` while today is
  `2026-09-26`; M3-F9). Expected: excluded from comparison; a future
  file must not block drafts.
- F16 reply file hand-edited after posting (body differs from what
  actually went to X; M3-F19). Expected: dedupe compares against file
  content as-is; drift from the posted tweet is a documented
  limitation, not detected or corrected here.
- F17 two HIGH tweets in the same batch yielding near-identical drafts
  (two verifier-model threads, worker drafts the same false-positive
  paragraph twice). Expected: first passes, second is flagged for
  rewrite — intra-batch dedupe applies the same near-identical rule
  between drafts, not just against persisted files.
- F18 draft identical to an unconfirmed (never persisted) draft from
  the previous run (operator declined it, R6 stored nothing).
  Expected: passes — dedupe is against persisted reply files only.
  Re-proposing a declined draft is allowed; the operator already saw
  it once and decides again.

## Concurrency

- F19 reply file written by a concurrent run mid-dedupe (manual
  `schedule run` overlapping the scheduled run; installed schedule
  uses `--overlap skip` so this is manual-only). Expected: no locking —
  atomic rename (M3-F20/F21) means the listing either sees the complete
  new file or misses it; at worst a draft is proposed once more, never
  corrupted or half-compared.
- F20 two overlapping runs drafting the same reply before either is
  confirmed/persisted. Expected: both pass dedupe (nothing persisted
  yet for either to match); no cross-run coordination. The operator
  seeing two identical proposals is the backstop; once one is
  confirmed and persisted via R6, the next run blocks repeats.
