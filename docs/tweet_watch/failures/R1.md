# tweet_watch R1 (watchlist ensure and read) — failure modes

Scope: on every run, ensure
`/Users/sergii/.ai/knowledge/media/x/watchlist.md` exists; if missing,
create it with exactly these 5 seed handles, one per line: `omarsar0`,
`typesafeai`, `cloneisjun`, `goodhartproof`, `SakanaAILabs`. Then return
the ordered handle list via M1 (blank lines / `#` comments ignored;
leading `@` stripped). Parsing edge cases live in M1; this file covers
the ensure/create/read contract only.

## Bad or missing input

- F1 missing watchlist file. Expected: create it with exactly the 5 seeds
  in the spec order, one handle per line plus a single trailing newline,
  then return the 5 handles in that order. Not an error.
- F2 existing file is never overwritten — not when it is empty, not when
  it holds custom handles, not when every line is invalid. Expected:
  return M1's parse of the file as-is (possibly `[]`); seeding happens
  only on missing file, never as a repair.
- F3 watchlist path is a directory. Expected: abort with an error naming
  the watchlist path; do not delete/rename it, do not fall back to seeds,
  do not touch state.
- F4 watchlist unreadable (permissions, e.g. `chmod 000`). Expected: abort
  with an error naming the watchlist path; do not fall back to seeds
  (that would mask the operator's list) and do not touch state.

## Boundary values

- F5 existing but empty file (0 bytes). Expected: return `[]`; the run
  fetches nothing, proposes nothing, leaves state untouched. Missing
  triggers seeding (F1); empty never does.
- F6 comment-only / whitespace-only file. Expected: same as F5 — return
  `[]`, no reseed, no error.
- F7 seed file content exactness. Expected: the created file contains
  exactly the 5 handles in spec order, `SakanaAILabs` keeping its case,
  one per line, LF endings, single trailing newline, no BOM, no comments.

## External errors

- F8 parent dir missing (`media/x/` gone). Expected: `mkdir -p` the parent,
  then create the seed file per F1. Reads never fail for a missing parent.
- F9 create fails (read-only dir, disk full). Expected: abort with an error
  naming the watchlist path and the OS error; no fetch, no proposals, no
  state write.
- F10 file disappears or becomes unreadable between ensure and read
  (operator deletes it mid-run). Expected: abort with an error naming the
  path; do not retry the create loop more than once (a second miss means
  something external is racing the run).

## Wrong state

- F11 existing file with garbage lines (spaces inside a line, `user!x`,
  truncated write from a killed prior run). Expected: treated as an
  existing file — NOT reseeded or repaired; M1 passes non-blank,
  non-comment lines through and the failure surfaces at fetch (M2) naming
  the handle. Recovery: operator edits or deletes the file per RUNBOOK
  (delete -> next run reseeds via F1), then re-runs.
- F12 seed write must be atomic (temp file + rename). Expected: a killed
  run never leaves a half-written watchlist behind, so F11-via-crash
  cannot happen through R1 itself.

## Concurrency

- F13 two runs start with the file missing (manual `schedule run` racing
  the scheduled run; the installed schedule uses `--overlap skip` so this
  is manual-only). Expected: both attempt the atomic create from F12; one
  wins, the loser reads the winner's file. Either way both runs proceed
  with the same 5 seeds; no error, no duplicate lines, no merged file.
- F14 overlapping runs with an existing file. Expected: no conflict — the
  ensure step is a pure existence check and the read is stateless; both
  runs get the same list.
